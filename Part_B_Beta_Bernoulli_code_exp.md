## The big picture in one paragraph

A fruit-picking robot sometimes succeeds and sometimes fails. Its true success rate, called `θ` (theta), is unknown. We watched it in three batches: 6 of 10, then 16 of 20, then 63 of 70 attempts succeeded (85 of 100 in total). Instead of a single guess for `θ`, Bayesian learning keeps a whole curve of beliefs about it, a Beta distribution with two numbers `α` (alpha) and `β` (beta). It starts at `Beta(2, 3)` (the prior), and after each batch you simply add the successes to `α` and the failures to `β`, ending at `Beta(87, 18)` (the posterior). The notebook then asks: how likely is the next attempt to succeed, what range is `θ` probably in, and is `P(θ > 0.8)` at least 0.95, the rule for deploying the robot? (Answer: 0.788, so no.) Finally it checks how much the starting belief (the prior) affects the answers.

Sections: B1 sets up the model (Cells 4–5), B2 updates beliefs (Cells 6–10), B3 measures uncertainty and makes the decision (Cells 11–16), B4 tests other priors (Cells 16–20), and Cell 21 saves a summary.

## Cell 4 (markdown, `id 958a3319`): B1, the model

No code, but it introduces every idea the later cells use.

- Bernoulli: one attempt is either a success (1) or a failure (0). Success happens with probability `θ`.
- Beta: a curve over all possible values of `θ` between 0 and 1, showing how believable each value is. It has two knobs, `α` and `β`.
- `X_i` versus `θ`: `X_i` is what you see (one attempt's 0 or 1). `θ` is hidden and is the thing we learn about.
- Density is not probability: a curve's height can be above 1. Only areas under the curve are probabilities (Cell 15 shows this).
- Conditional independence: if you knew `θ` exactly, one attempt would tell you nothing about the next. But since you don't know `θ`, seeing a success makes you think `θ` is higher, so you expect more successes. Cell 5 demonstrates this.

### The Beta distribution, simply

Think of `α` and `β` as a tally of successes and failures that you start with in your head before seeing any data (roughly, `α − 1` imagined successes and `β − 1` imagined failures).

- `Beta(1, 1)`: no imagined attempts. Every `θ` from 0 to 1 is equally believable (a flat line).
- `Beta(2, 3)`: like having seen 1 success and 2 failures. You lean towards a low `θ`. Its average is `α / (α + β) = 2 / 5 = 0.4`.
- `Beta(87, 18)`: lots of evidence. The curve is a tall, narrow peak near 0.83.

The bigger `α + β` is, the more "sure" the curve is (taller and narrower). The ratio `α / (α + β)` sets where the middle is.

Sample output, the height of the prior curve `Beta(2, 3)` at three values of `θ`:

```text
>>> stats.beta(2, 3).pdf([0.2, 0.4, 0.8])
[1.536 1.728 0.384]
```

`θ = 0.4` is about 4.5 times as believable as `θ = 0.8` under this prior. Note the heights 1.536 and 1.728 are above 1: that is allowed for a density.

One claim in this cell does not match the notebook's own numbers. It says "`f(0.8) = 4.6` is perfectly legitimate", but the final posterior's height at 0.8 is 7.256 (Cell 15). The closest values elsewhere in the notebook are 4.85 for `Beta(86,16)` and 4.41 for `Beta(93,17)`. The point being made (a density above 1 is fine) is correct, but the number should probably read `f(0.8) ≈ 7.26`.

## Cell 5 (code, `id 9812c05d`): Are attempts independent? (a simulation)

### Part 1: the "marginal" case, where θ is unknown

```python
rng = np.random.default_rng(SEED)
th = rng.beta(ALPHA0, BETA0, 400_000)                     # theta ~ prior
x1 = (rng.random(400_000) < th).astype(int)               # X1 | theta
x2 = (rng.random(400_000) < th).astype(int)               # X2 | theta, same theta
```

This simulates 400,000 imaginary robots:

- `rng.beta(2, 3, 400_000)` draws 400,000 random success rates from the prior. Each robot gets its own `θ`.
- `x1`: each robot makes attempt 1. It is a success if a random number is below that robot's `θ`. This is the same "`u < p`" trick as Part A Cell 9.
- `x2`: each robot makes attempt 2 with the same `θ`.
- `.astype(int)` turns True/False into 1/0.

Sample output (first 5 robots):

```text
>>> th[:5].round(4)                    # each robot's hidden success rate
[0.203  0.6962 0.5062 0.5076 0.3526]
>>> u[:5].round(4)                     # the random numbers used for attempt 1
[0.5425 0.3289 0.8442 0.0973 0.2714]
>>> u[:5] < th[:5]                     # success if u < theta
[False  True False  True  True]
>>> x1[:5]
[0 1 0 1 1]
>>> x2[:5]
[0 0 0 1 1]
>>> (x1 * x2)[:5]                      # 1 only if BOTH attempts succeeded
[0 0 0 1 1]
```

(`.round(4)` just shortens the printout to 4 decimals. `u` is my name for the `rng.random(400_000)` array, which the notebook does not store.)

```python
print(f"  P(X1=1, X2=1)      = {(x1*x2).mean():.4f}")
print(f"  P(X1=1)P(X2=1)     = {x1.mean()*x2.mean():.4f}")
print(f"  P(X2=1 | X1=1)     = {x2[x1==1].mean():.4f}")
print(f"  P(X2=1 | X1=0)     = {x2[x1==0].mean():.4f}")
```

- `x1.mean()` is the fraction of robots whose first attempt succeeded (about 0.40, the prior mean).
- `x1 * x2` is 1 only when both are 1. Its mean is the chance of two successes in a row: 0.2001.
- If the attempts were independent, that would equal `0.40 × 0.40 = 0.16`. It does not (0.20), so they are not independent.
- `x2[x1 == 1]` is boolean indexing (Part A Cell 7): keep attempt 2 only for robots whose attempt 1 succeeded. Its mean is 0.50. For robots whose attempt 1 failed, it is 0.33.

### Why seeing a success changes your guess, simply

Imagine a bag of coins, some fair and some biased, and you pick one at random. If the first flip lands heads, you start to suspect you picked a heads-heavy coin, so you expect heads more on the next flip. The flips are not linked to each other directly. They are linked through the coin you do not know.

Here the "coin" is `θ`. A success on attempt 1 is more likely if the robot has a high `θ`, so among robots that succeeded the average `θ` is higher (0.50 instead of 0.40), and they succeed more on attempt 2.

The exact values match the simulation: with a `Beta(2,3)` prior, `P(X2=1 | X1=1) = E[θ²] / E[θ] = 0.2 / 0.4 = 0.5` and `P(X2=1 | X1=0) = 1/3 ≈ 0.333`. (I worked these out separately; the notebook only simulates.)

### Part 2: the "conditional" case, where θ is fixed

```python
fixed = 0.55
xa = (rng.random(400_000) < fixed).astype(int)
xb = (rng.random(400_000) < fixed).astype(int)
```

Now every robot has the same known `θ = 0.55`. Attempt b succeeds 55% of the time whether attempt a succeeded (0.5506) or not (0.5496). The tiny difference is just random noise. Once `θ` is known, the attempts really are independent.

## Cell 6 (markdown, `id 69a6b7b1`): B2, the update rule and the three point estimates

The key result, derived with Bayes' rule:

```text
prior Beta(α, β)  +  s successes and f failures  ->  posterior Beta(α + s, β + f)
```

It also defines the three single-number guesses for `θ` that later cells compare:

| Name | Formula | In words |
|---|---|---|
| ML (maximum likelihood) | `s / n` | The plain success rate. Ignores the prior. |
| Posterior mean | `α / (α + β)` | The average of the belief curve. |
| MAP (maximum a posteriori) | `(α − 1) / (α + β − 2)` | The peak of the belief curve. |

### Conjugate updating, simply

Keep a scoreboard with two columns:

| | Successes column (`α`) | Failures column (`β`) |
|---|---|---|
| Start (prior) | 2 | 3 |
| Batch 1: +6, +4 | 8 | 7 |
| Batch 2: +16, +4 | 24 | 11 |
| Batch 3: +63, +7 | 87 | 18 |

That really is the whole of Bayesian updating for this model. "Conjugate" means the answer stays in the same family (Beta in, Beta out), so you never need anything harder than addition.

Because it is only addition, the order does not matter. Batches 1, 2, 3 or 3, 1, 2, or all 100 attempts at once all end at `Beta(87, 18)`. Cell 8 checks this.

Worked example for the final posterior `Beta(87, 18)`:

- ML = 85 / 100 = 0.85
- Posterior mean = 87 / (87 + 18) = 87 / 105 = 0.8286
- MAP = (87 − 1) / (87 + 18 − 2) = 86 / 103 = 0.8350

The posterior mean is lower than ML because the prior's imagined failures pull it down a little. MAP sits in between.

## Cell 7 (code, `id da7da035`): Sequential updating

### Two helper functions

```python
def beta_update(alpha, beta, s, f):
    return alpha + s, beta + f
```

The whole update rule from Cell 6 in one line. It returns two numbers (a tuple).

```python
def posterior_summary(alpha, beta, label, n_cum, s_cum):
    d = stats.beta(alpha, beta)
    mode = (alpha - 1) / (alpha + beta - 2) if (alpha > 1 and beta > 1) else np.nan
    lo, hi = d.ppf(0.025), d.ppf(0.975)
    return {"stage": label, "alpha": alpha, "beta": beta, ...,
            "ML (s/n)": (s_cum / n_cum) if n_cum else np.nan,
            "posterior mean": alpha / (alpha + beta),
            "MAP (mode)": mode,
            "posterior sd": d.std(),
            "95% CI low": lo, "95% CI high": hi, "CI width": hi - lo,
            "P(theta > 0.8)": d.sf(THRESHOLD)}
```

This builds one row of results for a `Beta(alpha, beta)` belief curve.

- `d = stats.beta(alpha, beta)` creates a SciPy distribution object. You can ask it questions with methods:

| Method | Question it answers | Example for `Beta(8, 7)` |
|---|---|---|
| `d.mean()` | Average value of `θ` | 0.5333 |
| `d.std()` | Standard deviation (how spread out) | 0.1247 |
| `d.pdf(x)` | Height of the curve at `x` (density) | — |
| `d.cdf(x)` | Area to the left of `x`: `P(θ ≤ x)` | `d.cdf(0.8)` = 0.9884 |
| `d.sf(x)` | Area to the right of `x`: `P(θ > x)` ("survival function", = `1 − cdf`) | `d.sf(0.8)` = 0.0116 |
| `d.ppf(q)` | The reverse of `cdf`: which `x` has area `q` to its left? ("percent point function") | `d.ppf(0.025)` = 0.2886 |

- `mode` only exists when both `alpha > 1` and `beta > 1`. Otherwise the curve has no peak inside (0, 1). In that case it uses `np.nan`, "not a number".
- `lo, hi = d.ppf(0.025), d.ppf(0.975)` gives the 95% credible interval: cut 2.5% of the area off each end.
- `(s_cum / n_cum) if n_cum else np.nan`: for the prior, no attempts have been made (`n_cum = 0`) and dividing by 0 would crash. `if n_cum` is False when `n_cum` is 0.

Sample output for the row after batch 1:

```text
>>> d = stats.beta(8, 7)
>>> d.mean(), d.std()
(0.5333333333333333, 0.12472191289246472)
>>> d.ppf(0.025), d.ppf(0.975)        # 95% credible interval
(0.28860940003830743, 0.7696394585519376)
>>> d.sf(0.8), d.cdf(0.8)             # the two always add up to 1
(0.01160991358975999, 0.98839008641024)
```

### The update loop

```python
rows = [posterior_summary(ALPHA0, BETA0, "prior Beta(2,3)", 0, 0)]
a, b = ALPHA0, BETA0
n_cum = s_cum = 0
seq_params = [(ALPHA0, BETA0)]
for bt in BATCHES:
    a, b = beta_update(a, b, bt["s"], bt["f"])
    n_cum += bt["n"]; s_cum += bt["s"]
    seq_params.append((a, b))
    rows.append(posterior_summary(a, b, f"after batch {bt['batch']}", n_cum, s_cum))
```

- It starts with a row for the prior, then loops over the three batches.
- `a, b = beta_update(a, b, ...)`: each batch updates the current belief, not the original prior. The output of one step is the input to the next.
- `n_cum = s_cum = 0` sets both to 0 in one line. `n_cum += bt["n"]` keeps a running total (cumulative = "so far"), needed for the ML column.
- `seq_params` stores each `(α, β)` pair for plotting in Cell 9.

Sample output, what `a, b` become each time round the loop:

```text
Beta(2.0,3.0) + 6 succ, 4 fail -> Beta(8.0,7.0)
Beta(8.0,7.0) + 16 succ, 4 fail -> Beta(24.0,11.0)
Beta(24.0,11.0) + 63 succ, 7 fail -> Beta(87.0,18.0)
```

```python
A_FINAL, B_FINAL = a, b
POST = stats.beta(A_FINAL, B_FINAL)
```

The final posterior `Beta(87, 18)` is stored as `POST`. Cells 8–16 and 21 all use it.

Reading the printed table: as data comes in, the standard deviation shrinks (0.200 → 0.125 → 0.077 → 0.037), and ML, mean and MAP move closer together.

### Check 2: the shortcut versus brute force

This checks the formula `Beta(α + s, β + f)` without using it, by applying Bayes' rule directly on a fine grid of `θ` values.

```python
grid = np.linspace(1e-6, 1 - 1e-6, 200_001)
```

`np.linspace(start, stop, count)` makes `count` evenly spaced numbers. Here that is 200,001 values from 0.000001 to 0.999999. It avoids exactly 0 and 1 because `log(0)` is minus infinity.

```text
>>> grid[:3], grid[-1], len(grid)
([1.000000e-06 5.999990e-06 1.099998e-05], 0.999999, 200001)
```

```python
log_post = ((ALPHA0 - 1) * np.log(grid) + (BETA0 - 1) * np.log1p(-grid)
            + TOTAL_S * np.log(grid) + (TOTAL_N - TOTAL_S) * np.log1p(-grid))
```

This is `log(prior × likelihood)` at every grid point, using the unnormalised formulas `θ^(α−1)(1−θ)^(β−1) × θ^s(1−θ)^f`.

- Logs turn multiplying into adding, and powers into multiplying.
- `np.log1p(-grid)` is `log(1 − grid)`, computed more accurately for small values (`log1p(x)` means `log(1 + x)`).

Why logs? `θ^86` for `θ = 0.5` is about `10^−26`. Multiplying numbers like that can underflow to 0. Their logs are ordinary-sized numbers.

```python
w = np.exp(log_post - log_post.max())
num_pdf = w / integrate.trapezoid(w, grid)
```

- Subtracting the maximum before `np.exp` makes the largest value exactly `exp(0) = 1` and the rest smaller. This is a standard trick to keep numbers in a safe range.
- `integrate.trapezoid(w, grid)` estimates the area under the curve by summing thin trapezoids. Dividing by it makes the total area 1, so the curve becomes a proper density.

Sample output at three grid points (θ ≈ 0, 0.5 and 0.83):

```text
>>> log_post[[0, 100000, 166000]]
[-1188.13392498   -71.3941596    -46.14761242]
>>> w[[0, 100000, 166000]]           # after exp(log_post - max)
[0.00000000e+00 1.07558843e-11 9.91019606e-01]
>>> integrate.trapezoid(w, grid)     # area before normalising
0.09126615935970664
```

`np.exp(-1142)` (that is, `-1188.13 − (−46.14)`) is so small that it rounds to exactly 0. That is fine, since `θ ≈ 0` is essentially impossible after 85 successes.

```python
closed = POST.pdf(grid)
print(... np.abs(num_pdf - closed).max() ...)
```

This compares the brute-force curve with SciPy's `Beta(87, 18)` curve at all 200,001 points. The largest difference is `1.3e-13`, rounding noise. The shortcut is exact.

## Cell 11 (markdown, `id d1f4d0ce`): B3, the three uncertainty quantities

It defines the three answers that Cell 12 calculates:

1. Posterior predictive: the chance the next attempt succeeds.
2. 95% credible interval: a range that `θ` lies in with 95% probability.
3. `P(θ > 0.8 | D)`: the chance the true success rate is above 0.8, the number the deployment rule needs.

### The three quantities, simply

Imagine the belief curve `Beta(87, 18)` as a pile of 1,000 sand grains spread along a ruler from 0 to 1. Each grain is one possible value of `θ`, and the pile is highest near 0.83.

- Predictive: pick a grain at random, then flip a coin with that success rate. On average the coin comes up "success" 82.86% of the time. That is the average grain position, `87 / 105`. It averages over every possible `θ` instead of trusting one guess.
- 95% credible interval: push 25 grains (2.5%) off the left end and 25 off the right end. The range the remaining 950 grains cover is [0.751, 0.894].
- `P(θ > 0.8)`: count the grains to the right of 0.8. About 788 of 1,000 are there, so 0.788.

The cell also points out that the predictive equals the posterior mean only because "chance of success" is `θ` itself. For "both of the next two attempts succeed" you would need the average of `θ²`, which is not `(average θ)²`.

## Cell 13 (code, `id 660adcfe`): Monte Carlo check of `P(θ > 0.8)`

Monte Carlo means "estimate it by drawing lots of random samples and counting". This checks the SciPy answer with a completely different method.

```python

mc_se = float(np.sqrt(mc_p * (1 - mc_p) / N_DRAWS))
```

- `rng_mc.beta(87, 18, 200_000)` draws 200,000 random values of `θ` from the posterior. These are the "sand grains" from Cell 11.
- `draws > THRESHOLD` gives True/False for each; `.mean()` is the fraction above 0.8.
- `mc_se` is the standard error, the typical size of the random error in a fraction estimated from N samples: `sqrt(p(1 − p) / N)`.

Sample output:

```text

[0.7685 0.8803 0.853  0.8498 0.7879 0.8855]

>>> (draws > 0.8).sum()             # how many of the 200,000 are above 0.8
157376
>>> mc_p                            # 157376 / 200000
0.78688
>>> mc_se
0.0009156960893222161
```

The analytic answer is 0.788267, so the simulated one is off by 0.001387. Divided by the standard error, that is `0.001387 / 0.000916 = 1.51` standard errors. A gap under about 2 standard errors is normal random noise.

## Cell 14 (code, `id fdf38542`): The deployment decision


- The `'A' if meets else 'B'` inside the f-string picks which text to print.
- The shortfall is `0.95 − 0.7883 = 0.1617`.

### The decision, simply

The rule is not "is my best guess above 0.8?" (it is: 0.83 or 0.85). The rule is "am I at least 95% sure the true rate is above 0.8?". With only 100 attempts, about 21% of the belief curve is still below 0.8, so you can only be 79% sure.

Analogy: a student averages 85% on practice tests, and the pass mark is 80%. Their average is above the pass mark, but after only a few tests you cannot be 95% sure they will pass, because a couple of bad tests could pull them down. You would want to see more tests first.

### How much more data would be enough?

```python
rate = TOTAL_S / TOTAL_N
for extra in [0, 50, 100, 200, 300, 400, 500, 700]:
    s_ex = int(round(rate * extra))
    aa, bb = A_FINAL + s_ex, B_FINAL + (extra - s_ex)
    pv = stats.beta(aa, bb).sf(THRESHOLD)
```

"What if the robot made `extra` more attempts and kept succeeding 85% of the time?"

- `s_ex` is the expected number of extra successes, rounded to a whole number.
- `aa, bb` is the belief after adding them (Cell 6's scoreboard rule).
- `pv` is the new `P(θ > 0.8)`.

The table shows the rule is first met somewhere between +100 (0.9299) and +200 (0.9744) attempts. I ran the gaps in between in steps of 10. It first passes 0.95 at +140 attempts (0.9535):

```text

 100     85   0.9299
 110     94   0.9473
 120    102   0.9430      <- dips below 110's value (rounding, see below)
 130    110   0.9387      <- 0.85 × 130 = 110.5 rounded DOWN to 110
 140    119   0.9535      <- first value above 0.95
 150    128   0.9650
```

The small dips come from rounding `s_ex` to a whole number: 110 extra attempts assume 94 successes (85.5%), while 130 assume only 110 (84.6%).

Python rounding detail: `round(0.85 * 50)` gives 42, not 43. `0.85 * 50` is exactly 42.5, and Python's `round` sends exact halves to the nearest even whole number ("banker's rounding"): `round(42.5) = 42`, `round(93.5) = 94`, `round(110.5) = 110`. So the +50 row actually assumes 42/50 = 84%, not 85%. This is a tiny effect.

## Cell 15 (code, `id 40eb112d`): A density value is not a probability

```python
print(f"  f(0.8)                     = {POST.pdf(THRESHOLD):.6f}")
for w in (0.01, 0.001):
    exact_w = POST.cdf(THRESHOLD + w / 2) - POST.cdf(THRESHOLD - w / 2)
    print(... exact_w ... POST.pdf(THRESHOLD)*w ...)
```

- `POST.pdf(0.8)` = 7.2556 is the height of the curve at 0.8. It is bigger than 1, so it clearly cannot be a probability.
- `cdf(0.805) − cdf(0.795)` is the area (= probability) of the narrow strip from 0.795 to 0.805.
- That area is about height × width: `7.2556 × 0.01 = 0.0726`.

### Density versus probability, simply

Density is like population density: "7.26 people per square km" is not a number of people. You only get a number of people when you multiply by an area. Likewise a curve height of 7.26 only becomes a probability when you multiply by a width of `θ`:

```text
strip width   exact area (cdf difference)   height × width
0.01          0.072540                      7.2556 × 0.01  = 0.072556
0.001         0.007256                      7.2556 × 0.001 = 0.007256
```

The narrower the strip, the better "height × width" matches. A single point has width 0, so its probability is exactly 0.

The last line finds the curve's highest point by checking 10,001 values: the peak is 10.957, at the MAP 0.8350.

## Cell 18 (code, `id 3caeec09`): ML versus MAP under the flat prior

### Part 1: they are equal

```python
for stage, n_c, s_c in [("after batch 1", BATCHES[0]["n"], BATCHES[0]["s"]),
                        ("after all batches", TOTAL_N, TOTAL_S)]:
    aa, bb = 1.0 + s_c, 1.0 + (n_c - s_c)
    mode = (aa - 1) / (aa + bb - 2)
    ml = s_c / n_c
    mean = aa / (aa + bb)
    print(... np.isclose(ml, mode) ...)
```

With the flat prior `Beta(1,1)`, the posterior after `s` successes in `n` attempts is `Beta(1 + s, 1 + n − s)`. Put that into the MAP formula:

```text
MAP = (1 + s − 1) / (1 + s + 1 + n − s − 2) = s / n = ML
```

Worked example after batch 1 (s = 6, n = 10): posterior `Beta(7, 5)`:

- ML = 6 / 10 = 0.600
- MAP = (7 − 1) / (7 + 5 − 2) = 6 / 10 = 0.600 (the same)
- mean = 7 / (7 + 5) = 7 / 12 = 0.5833 (different)

`np.isclose(ml, mode)` is used instead of `ml == mode` because decimal arithmetic can leave tiny rounding differences:

```text
>>> 0.6 == 0.6000000000000001
False
>>> np.isclose(0.6, 0.6000000000000001)
True
```

### ML versus MAP, simply

A flat prior says "I have no preference", so the peak of the belief curve lands exactly where the data alone puts it. That is the ML value. But the Bayesian answer is the whole curve, not just its peak. Its average, `(s + 1) / (n + 2)`, adds one imagined success and one imagined failure (this is called Laplace smoothing), so it is pulled a little towards 0.5.

### Part 2: an extreme case, 5 out of 5

```python
n_x, s_x = 5, 5
d_x = stats.beta(1 + s_x, 1 + n_x - s_x)       # Beta(6, 1)
```

Sample output:

```text
ML                     = 1.0000   (5/5)
MAP (uniform prior)    = 1.0000
posterior predictive   = 0.8571   (6/7)
95% CI                 = [0.5407, 0.9958]
P(theta > 0.8)         = 0.7379
```

ML says "100% success, it can never fail", after only 5 tries. The Bayesian answer says "about 86% for the next try, and the true rate could be as low as 0.54". That is the more sensible conclusion from 5 attempts. This is why the full posterior matters most when there is little data.
